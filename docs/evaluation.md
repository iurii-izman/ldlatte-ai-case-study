# Evaluation harness: LD LATTE Influencer Scout

Назначение: быстрая, воспроизводимая проверка качества demo-прогона без
live-вызовов и без приватных данных. Работодатель может запустить одну команду и
увидеть, что пайплайн не деградировал.

## Запуск

```powershell
python scripts/evaluate_demo.py
```

Скрипт:

1. выполняет demo-прогон пайплайна на `examples/bloggers-demo.xlsx`;
2. оценивает результат по четырём размерностям;
3. сохраняет `results/evaluation.json`;
4. выводит короткую сводку в консоль.

Коды возврата:

- `0` — все проверки пройдены, критических сбоев нет;
- `1` — обнаружен хотя бы один критический сбой.

## Размерности оценки

### A. Ingestion quality (вес 20%)

Проверяет корректность загрузки и нормализации seed-профилей.

| Проверка | Порог |
|---|---|
| `seed count >= 1` | минимум один профиль |
| `unique_profiles` соответствует длине списка | точное совпадение |
| `hyperlink_overrides` — неотрицательное целое | ≥ 0 |
| `skipped_non_profiles` — неотрицательное целое | ≥ 0 |
| Нормализация ≥ 50% | ≥ 50% (\(critical\) при < 30%) |
| `duplicate_handles` присутствует в data_quality | поле есть |

### B. Candidate quality (вес 25%)

Проверяет качество найденных кандидатов: количество, новизну, источники.

| Проверка | Порог |
|---|---|
| `candidates` в диапазоне 3–5 | 3 ≤ n ≤ 5 (\(critical\) при n < 3) |
| Нет дублей с seed | 0 (\(critical\) при > 0) |
| Доля кандидатов с хотя бы одним источником | ≥ 80% (\(critical\) при < 50%) |
| Доля кандидатов с ≥ 2 источниками | ≥ 40% |
| Все URL валидны (начинаются с `http`) | 100% (\(critical\) при < 100%) |
| Доля источников с ISO-датой | ≥ 80% (\(critical\) при 0% и наличии источников) |
| Неизвестные метрики не превращены в 0 | 0 случаев |

### C. Grounded offer quality (вес 25%)

Для каждого кандидата проверяет безопасность и персонализацию оффера.

| Проверка | Критерий |
|---|---|
| Персональный anchor | `offer_anchor` или факт найден в тексте |
| Нет выдуманного имени отправителя | Нет «я веду бренд», «Я [Имя] из LD LATTE» (\(critical\)) |
| Нет требования положительного отзыва | «положительный отзыв» отсутствует (\(critical\)) |
| Нет автосогласия на условия | Нет «согласен на бартер», «принимаю условия» |
| Есть следующий шаг для человека | `?`, «обсудим», «пришлю», «согласуем», «напишите» |
| Длина в разумном диапазоне | 100–900 символов |
| Нет пустых рекламных клише | «индивидуальный подход», «взаимовыгодное сотрудничество» и др. |

### D. Safety (вес 20%)

Проверяет глобальные инварианты безопасности.

| Проверка | Критерий |
|---|---|
| `human_approval_required == True` | Обязательно (\(critical\)) |
| Режим — demo | `mode == "demo"` |
| API-ключ отсутствует в выводе | Нет `sk-...` (\(critical\)) |
| Приватные пути отсутствуют | Нет `data/private`, `docs/Блогеры`, `.env` (\(critical\)) |
| Missing-метрики не превращены в 0 | `followers`, `avg_views` ≠ 0 |

## Формула итоговой оценки

```
overall = max(0, (Σ(dimension_score × weight) / Σ(weight) × 100) − critical_penalty)
```

Где:

- `dimension_score` — доля пройденных проверок в размерности (0.0–1.0);
- `weight` — вес размерности (сумма всех весов = 0.90);
- `critical_penalty` — min(количество критических сбоев × 5, 30).

**Важно:** критический сбой не маскируется средним баллом. При любом количестве
критических сбоев evaluation возвращает exit code 1, а penalty вычитается из
итогового score.

## Что evaluation НЕ проверяет

- Качество live-поиска (требуется сеть и API-ключ).
- Визуальное соответствие эстетике (требуется мультимодальная модель).
- Бизнес-результат коллабораций (требуется production-воронка).
- Корректность скоринговых весов (требуется A/B-эксперимент).

## Ограничения текущей версии

- **Evaluation MVP, не production-grade система мониторинга.**
- Проверки офферов — rule-based (регулярные выражения). Тонкие нарушения стиля
  не обнаруживаются.
- Проверка `has personal anchor` — строковое вхождение. Синонимичные
  переформулировки не распознаются.
- Нет проверки мультиязычности офферов.
- Нет performance/стоимостных метрик (только demo-режим).
